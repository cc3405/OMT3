# OMT3 设计冻结前完整审查记录（2026-10-31）

> 审查对象：`docs/full-audit-2026-10-30` 分支当前仓库内容。  
> 审查范围：根目录、docs、OM 赛题文本、ESP32-S3 固件、Python 替代算法及测试；并对照 2026–2027 Problem 1、Program Guide 与截至审查日可见的 General Clarifications。  
> 审查性质：文件/规则/代码静态审查，不是工程认证、赛事官方裁定、真实硬件测试或现场验收。  
> 结论：**发现阻塞项与文档冲突，当前不能判定“检查无误”，因此本记录明确列出冻结前必须关闭的事项。**

## 1. 总体结论

项目处于“方案和采购候选已建立、核心实物尚未完成验证”的阶段。仓库中有可用的项目起点：Division II 设计基线、规则追踪、购物车与道具选型、独立卸载装置概念、ESP32-S3 点动固件、Python 替代算法和 6 个算法单元测试。

但当前不能直接按旧 BOM 一次采购并照图拼装。原因包括：
1. **购物车选型冲突**：BOM 第 12/13 节仍把 60L 金属网篮车写成默认采购件；更新的 `CART_AND_PROP_SELECTION.md` 已选择 Sakugi 80L 布篮折叠 wagon。两种车结构、框架和牵引点完全不同，旧 BOM 的 CART03/CART04、牵引杆、夹板和锁销不能直接照搬。
2. **乘坐车辆没有可制造工程设计**：缺少总装 CAD、材料截面、焊/螺栓节点、轮距/轴距、重心、载荷路径、制动、转向、乘员约束和结构校核。现有电机/底盘 BOM 不能证明可承载人员。
3. **卸载装置只有概念**：Division II 独立卸载台的尺寸参数全部 TBD；无实物、无图纸、无材料定尺、无测试证据。
4. **商品抓取机构未实现且非现有固件功能**：BOM 有 3 个舵机和 PCA9685 候选，但固件没有 PCA9685 初始化、舵机控制、抓取状态机；不能把候选采购项当作已实现模块。
5. **电气系统尚不能安全上电**：电机/舵机堵转电流、BTS7960 具体板型逻辑阈值、编码器输出电平、电池/BMS能力、保险丝和线径均未完成核算；硬件急停未实测。
6. **成本风险极高**：题面总成本上限 US$165。仅购物车和道具初步估算约 US$55–65，尚未包括原创乘坐车辆、驱动、电源、独立卸载台、电子件和演出/风格材料。不能声称当前采购方案能在上限内完成。
7. **规则追踪尚非最终版**：已确认 Division II 的团队设计基线，但正式报名/教练证据仍待归档；活动手册与赛题后续澄清仍须持续复核。
8. **测试状态不能升级**：测试文件存在不等于测试已运行；固件源码存在不等于 Arduino-ESP32 编译通过；所有硬件和整机测试均未测。

## 3. 仓库一致性与文档缺陷

### 3.1 购物车基线冲突（P0）
- `docs/COMPONENTS_BOM.md` 第 12/13 节：60L 金属网篮购物车为默认采购件，另列网篮夹板、脚轮、牵引转接件、快拆销。
- `docs/CART_AND_PROP_SELECTION.md`：更新选择 Sakugi 80L 折叠 wagon，标称 28×17×36 in，布篮+金属折叠框架，Walmart 参考价约 US$39.98。
- 结论：后者是当前较新的候选基线，但**尚未实物验收**。旧 BOM 的 60L 购物车专用件必须标记为“废止/待重新设计”，不可直接采购。

### 3.2 乘坐车辆与购物车概念混写
仓库中存在乘坐车辆的差速底盘、立柱/把手、车载抓取臂、拖挂购物车等多个子系统。必须在图纸中区分：
- 乘坐式原创车辆（队伍制作）；
- 可拆卸的商业/自制购物车（被车辆牵引）；
- 与车辆完全分离的独立卸载装置。
三者不能互相替代。购物车不能当乘坐车辆；车载舵机/翻斗不能当独立卸载台。

### 3.3 README 交叉链接问题
当前 README 的项目导航没有稳定地列出最新购物车选型文档；存在疑似字面 `\\n` 的链接分隔字符。应修正 README 并将本审查、拼装说明、理论报告、购物车选型和 BOM 版本统一列入导航。

### 3.4 BOM 采购可执行性不足
BOM 自己已经声明：CAD、尺寸、电流数据和实物接口未冻结；部分采购件只给候选规格，没有准确 SKU/链接/价格。不得将其称为“可一次下单的最终 BOM”。

## 4. 软件与固件静态审查

### 4.1 Python 替代算法
文件：`tools/substitution.py`。实现：
- 输入校验商品名和类别；
- 商品未缺货则保留原商品；
- 缺货时只筛选同类别、预算内、价格有效且有 ID 的候选；
- 按价格升序、ID 字典序确定结果；
- 无候选或预算无效时返回需人工协助。

`tests/test_substitution.py` 有 6 个用例：原商品有货、同类最低价、同价确定性、无候选、无效预算、必填字段缺失。**本次只确认测试源码存在和逻辑覆盖范围，未声称在当前环境实际运行通过。**尚缺多商品累计预算、重复 ID、无效候选、助理批准、库存输入可信度和整机接口测试。

### 4.2 ESP32-S3 固件
文件：`firmware/esp32_s3/esp32_s3.ino`。目前是串口手动点动 bring-up 骨架：
- 4 路 PWM、共享驱动使能、A 相编码器计数、2 个超声波、2 个限位输入；
- 上电默认禁用；运动脉冲 700ms 限时；超声波无回波/近障碍会停止；
- 没有自动路线、闭环里程、A/B 编码器方向、返航、车载遥控器、机械臂、购物车释放和完整任务状态机；
- 限位开关仅读取/显示，尚未按方向互锁危险运动；
- `lastCommandMs` 在启动运动时赋值，当前没有持续刷新；700ms 动作限时早于 1000ms watchdog，故 watchdog 目前主要是冗余保护，需重构其语义；
- 超声波读数采用阻塞式 `pulseIn`，每次最多等待 18ms；两个传感器顺序读取会影响控制循环响应；
- 软件停止不等于硬件急停；外部硬件急停仍需单独实现并测试。

以上是静态代码检查，不代表已在实物复现。Arduino-ESP32 版本/目标板编译仍未提供日志。

## 5. 电气与机械设计审查

### 5.1 电气风险
- ESP32-S3 GPIO 为 3.3V；HC-SR04 Echo 和可能的编码器 5V 输出必须适配，不能直连。
- BTS7960/IBT-2 模块版本差异、3.3V 逻辑高电平阈值、R_EN/L_EN接法必须按具体 SKU 核实。
- 电机额定/堵转电流未确认；不可据此选择电池 BMS、驱动器、保险丝、接触器、导线。
- 舵机峰值电流和堵转力矩未确认；10A UBEC 只是候选，不可视为已足够。
- 急停应通过硬件切断电机驱动能量，不应仅靠 MCU 软件命令。
- 电机电源、逻辑电源和舵机电源需分支设计；共地与大电流回路布局需按驱动器原理图确认。

### 5.2 乘坐车辆风险
在没有载荷路径、材料、焊缝/螺栓、轮轴/轮毂承载、轮距/轴距、重心、转向、制动和急停验证前，不能给出乘坐车辆的“照做即安全”拼装步骤。当前 BOM 里的 35kg/40kg 类参数若出现，只能当作需求输入，不能当作实测额定载荷或允许乘坐的依据。

### 5.3 独立卸载台
当前概念采用独立底座、定位区、可调接料平台、侧导轨、抽拉托盘、止挡和手柄。所有尺寸 TBD。需要先测三件实物、购物车篮底/篮口/高度和结账区位置，再冻结切割表。
