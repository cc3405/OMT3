# OMT3 OMER’s Shopping Service — 理论技术报告 v0.1

> 日期：2026-10-31  
> 项目组别设计基线：Division II（正式报名/教练凭证待归档）  
> 报告性质：理论方案与静态代码审查；非结构认证、非电气认证、非赛事官方裁定、非实机测试报告。**本报告中的Sakugi 80L布篮wagon选型已被2026-10-31统一设计包撤销；当前唯一购物车基线为中国大陆采购的60L金属网篮超市购物车。涉及购物车的旧尺寸/成本推演仅作历史背景，采购以主控文件为准。**

## 摘要

本项目拟实现一套 OMER 购物服务演示系统：原创乘坐式车辆牵引可拆卸购物车，接收三件商品订单；一件商品缺货时选择同类替代品并由购物助理批准；结账时使用队伍自制、与车辆分离的手动卸载装置，将三件物品放入结账区域；最后车辆按题面时序释放购物车并使其返回购物车区域。

当前仓库已具备 ESP32-S3 N16R8 低速点动固件骨架、Python 替代算法、6 个算法测试用例、60L金属网篮购物车（后续统一选型）与三件道具选型、Division II 独立卸载台概念。核心车辆结构、完整运动控制、抓取机构、独立卸载实物、拖挂释放闭环和全流程测试均未完成。故本报告给出理论架构、计算方法、风险与验证计划，不声称系统已经建成或安全可乘坐。

## 1. 需求与约束

### 1.1 功能需求
1. 车辆为队伍原创制作的可乘坐车辆，由乘坐在车上的队员操作；车辆移动时乘员不得触地。
2. 车辆连接可拆卸购物车并带其行进。
3. 购物助理在规定时序交接购物清单；缺货商品必须有替代品并经购物助理批准。
4. 三件有形且可见物品完成购物/结账。
5. Division II 使用队伍制作的独立卸载装置；装置不能连接车辆，可由队员直接人力操作。
6. 结账完成后，车辆继续行进，购物车越过起始线垂直平面；车辆停止后释放购物车，购物车进入购物车区域并静止；车辆保持在起始线上或其外侧。
7. 完整演出不超过 8 分钟；总成本上限 US$165，依当季 Program Guide 计价。

### 1.2 当前购物车与道具基线
- 购物车当前基线：60L紧凑型金属网篮超市购物车（中国大陆淘宝/天猫采购优先）；具体SKU和尺寸待核实。此前Sakugi 80L布篮wagon候选已撤销，不采购。
- 道具 1：空 500mL PET 瓶，团队原创标签。
- 道具 2：3in（约76mm）软质泡沫球。
- 道具 3：蓝色带盖盒作为请求物品，设为缺货；红色同类带盖盒作为替代品，由购物助理批准。
- 进入结账区的实际三件物品：PET 瓶、泡沫球、红色替代盒。

### 1.3 重要规则时序
2026-10-01 官方 General Clarification B9c 明确：计时开始时，购物清单必须在车辆越过起始线前交给车辆操作员。场地布局另有 2026-09-15 澄清。正式演练应按完整官方题面、2026–27 Program Guide 和最新澄清逐条复核。

## 2. 系统总体架构

### 2.1 三个不可混淆的物理系统
A. **乘坐式原创车辆**：差速驱动候选方案，含底盘、乘员支撑、驱动轮、转向/操控、制动、急停、电池与控制系统。尚无可制造 CAD 或结构验证。  
B. **可拆卸购物车**：当前选型为商用 Sakugi 80L 折叠 wagon；只承担购物物品运输，不作为乘坐车辆。由于布篮不是刚性承载框架，任何拖挂载荷只能传到金属承载框架，不能传到布料/布带。实际接口必须重新设计。  
C. **Division II 独立卸载台**：独立落地、手动操作，不连接车辆、不使用车辆供电或控制；由底座、购物车定位、可调接料平台、侧导轨、抽拉托盘、止挡与手柄构成。

### 2.2 功能流程状态机
建议采用明确状态机：

`WAIT_START → RECEIVE_ORDER → CHECK_STOCK → SELECT_SUBSTITUTE → WAIT_ASSISTANT_APPROVAL → LOAD_ITEMS → MOVE_TO_CHECKOUT → STOP_AND_POSITION_CART → MANUAL_UNLOAD → CHECK_ORDER → CROSS_START_PLANE → STOP_VEHICLE → RELEASE_CART → CART_RETURN → VERIFY_PARKED → DONE`

每个状态都必须定义：
- 进入条件；
- 允许的执行器动作；
- 成功判据；
- 超时/传感器异常/机械卡滞分支；
- 安全停止方式；
- 操作员可见的状态提示。

不得把“软件返回成功”当作物品已卸载或购物车已停入区域的物理证据。

## 3. 运动学理论（差速驱动候选）

设左右驱动轮线速度分别为 (v_L)、(v_R)，轮距为 (b)，车体中心线速度为 (v)，角速度为 (omega)，则理想无侧滑差速模型为：

[
v = rac{v_R+v_L}{2}
]

[
omega = rac{v_R-v_L}{b}
]

轮半径为 (r)、轮角速度为 (dot{	heta}_{L,R}) 时：

[
v_{L,R}=rdot{	heta}_{L,R}
]

该模型只适用于轮胎滚动且侧滑可忽略的近似情形。实际控制需要：
1. 测量左右轮有效滚动直径；
2. 测量轮距；
3. 读取编码器 A/B 两相并确定方向；
4. 用低速直行/原地转向标定比例误差；
5. 在比赛地面验证打滑、地毯/胶带阻力和负载影响。

当前固件只统计 A 相脉冲，不能可靠判定方向，也没有速度/距离闭环，因此尚不能实现可靠返航或精确停车。

## 4. 牵引与释放理论

购物车与车辆连接可视为一个受约束的拖挂系统。理想情况下，车辆牵引力至少要克服：
- 购物车滚动阻力；
- 轮子转向产生的侧向阻力；
- 地面不平引起的附加阻力；
- 加速时的惯性力；
- 转弯时购物车偏摆造成的侧向力。

可用简化关系估算：

[
F_{tow} approx C_{rr}mg + ma + F_{turn}
]

其中 (C_{rr}) 为滚动阻力系数，(m) 为购物车及物品总质量，(a) 为纵向加速度，(F_{turn}) 为转弯附加阻力。所有参数必须实测或从可靠数据表取得，不能用卖家“360lb承载”代替拖挂受力数据。

关键设计原则：
- 牵引点固定到金属承载框架；
- 不把牵引力传给布篮/布带；
- 使用允许俯仰/偏摆的接头并设置限位；
- 设置防脱二次保险；
- 释放机构应有明确的锁止/释放状态和断电安全状态；
- 释放动作发生在题面规定的越线、停车时序之后；
- 返区必须通过真实场地测试，不能只靠理论轨迹。

## 5. 结构与稳定性理论

乘坐式车辆的结构安全必须在设计阶段建立载荷路径：乘员载荷 → 支撑面/座椅 → 主框架 → 轴承/车轴/车轮 → 地面。任何装饰板、薄壁外壳或未核算的型材接头不得作为主要承载路径。

### 5.1 静态倾覆边界（理论）
对于简化横向支撑宽度 (t)、重心高度 (h_{CG})，静态侧倾临界角近似满足：

[
	an 	heta_{crit} approx rac{t/2}{h_{CG}}
]

该关系忽略动态转弯、轮胎变形、地面不平、乘员移动和结构弹性，只能用于早期理解；不能作为安全认证。重心高度越高、支撑宽度越窄，静态倾覆余量越小。

### 5.2 载荷与强度
需取得材料弹性模量、屈服强度、型材截面、螺栓等级、焊缝形式、连接偏心和载荷工况。关键构件需计算弯矩、剪力、局部屈曲、螺栓剪切/拉伸、连接撕裂及疲劳。没有这些输入时，不给出安全载荷或乘坐许可。

**当前结论：车辆承载能力未知。禁止真人乘坐测试。**

## 6. 电源与电气理论

### 6.1 电池容量
电池名义能量可用：

[
E_{Wh}=V_{nom}	imes C_{Ah}
]

但可用能量取决于电池化学体系、放电倍率、温度、BMS限制、截止电压和安全余量。不能仅凭“5000mAh”判断可带动两台电机。

### 6.2 电流预算
需要分别测量或获取：
- 电机空载电流、额定工作电流、启动/堵转电流；
- 驱动器连续电流、峰值电流与散热条件；
- 舵机空载/负载/堵转电流；
- ESP32、传感器、指示器的逻辑电流；
- DC-DC 在输入电压范围内的效率和热设计。

保险丝应保护线束与支路，按导线允许电流、驱动器、启动/堵转特性和实际布线核算；不能直接采用卖家宣传的峰值电流作为保险丝值。

### 6.3 电气安全边界
- ESP32-S3 GPIO 逻辑为 3.3V，5V Echo/编码器信号必须适配。
- 电机电源、逻辑电源、舵机电源应按电路设计分路；信号地按拓扑连接。
- 驱动使能脚要有外部下拉，确保 MCU 复位时默认禁用。
- 急停必须硬件切断电机驱动能量，不依赖软件。
- 电池充电必须使用适配电池化学体系的商用充电器，并由成人监督；按 Program Guide 的电池要求准备检查。

## 7. 抓取机构的理论评估（可选项）

当前仓库 BOM 有三舵机机械臂候选，但固件未实现。机械臂是否必要，应先验证比赛动作能否由规则允许的队员操作方式完成。若最终决定使用机械臂，必须对每个关节计算：

[
	au_{req} geq rac{m g L}{eta}
]

其中 (m) 是末端负载，(L) 是关节到负载重心的水平力臂，(eta) 综合传动效率与姿态因素。实际设计还需加入动态加速度、连杆自重和安全余量。舵机标称 kg·cm 不能直接等同于整个臂端可安全承载质量；供电电流也需按多舵机同时动作的峰值计算。

对当前三件道具：
- PET 瓶：圆柱表面，宜用宽软夹面夹持瓶身；
- 泡沫球：易压缩，宜用浅托杯/柔性包覆；
- 带盖盒：平面侧壁，可用平行夹爪，但需防滑。
若机械臂成本、质量或稳定性负担过高，应优先简化为人工取放/被动定位方案，并核对题面允许的操作方式。

## 8. 独立卸载台理论

建议采用无动力抽拉托盘方案。三件物品在整个转移过程应持续得到承托，避免自由跌落。

核心参数由实测决定：
- (L_{max}, W_{max}, H_{max})：三件物品最大尺寸；
- (M_{max})：最大单件质量；
- (H_{cart})：购物车篮底/篮口相对地面高度；
- (S_{travel})：购物车内取物位置至结账区放置位置的行程；
- (W_{guide})：导轨净宽；
- (L_{tray}, W_{tray})：托盘有效承托尺寸；
- (L_{base}, W_{base})：底座尺寸和支撑多边形。

设计验收：
1. 装置独立落地，不与车辆机械/电气连接；
2. 底座推拉托盘时不翘脚、不滑移、不倾覆；
3. 导轨平行，托盘不脱轨；
4. 软垫保护瓶、泡沫球和盒子；
5. 机械止挡限制行程；
6. 单件各 5 次转运无掉落/卡滞；
7. 三件连续 10 轮，目标至少 9/10 轮完整进入结账区，并记录失败原因；
8. 所有边缘倒圆，夹点可见且可避免。

## 9. 软件算法与系统集成

### 9.1 当前替代算法
`tools/substitution.py` 是纯 Python 决策函数。缺货时按同类别、预算内、最低价格选择，价格相同时按候选 ID 字典序决定；无候选时返回需人工协助。它不读取真实货架库存、不控制机械臂、不自动完成购物任务。

### 9.2 建议的系统接口
- 订单模块：商品 ID、类别、预算、数量；
- 库存输入：有货/缺货状态及其来源；
- 候选模块：替代商品 ID、类别、价格；
- 决策输出：保留原商品/选择替代/需要人工协助；
- 购物助理：独立确认替代品；
- 执行层：装载和卸载动作；
- 日志层：时间戳、输入、输出、人工批准、错误码。

### 9.3 固件改进重点
1. 将 A/B 编码器接入并验证方向；
2. 为限位开关增加运动方向互锁；
3. 传感器无回波/断线时锁定运动并要求人工复位；
4. 将阻塞式超声波采样改为非阻塞/定时采样或合理超时调度；
5. 重新定义 command watchdog，明确心跳刷新规则；
6. 增加物理遥控/操作界面和硬件急停；
7. 实现任务状态机和状态提示；
8. 编译、上板、记录每一版本；
9. 机械臂控制（如果采用）与独立卸载台保持完全分离。

## 10. 成本与可行性

Problem 1 总成本上限为 US$165。当前购物车和道具候选约 US$55–65；再加入 ESP32-S3 开发板候选 US$18.99，已知候选合计约 US$74–84，仍未计入：
- 原创乘坐车辆的结构材料、车轮、轴、驱动电机和传动；
- 电池之外的电气件、驱动器、线材、保险丝、急停、降压模块；
- 独立卸载台的板材、导轨、托盘、止挡、紧固件；
- 可选抓取机械臂；
- 演出布景、服装、艺术标签和音乐相关材料。

因此，**若从零购买全部系统，当前架构极可能超过 US$165**。可行的下一步不是假定预算够，而是：
1. 用现有材料/安全可复用材料降低成本；
2. 先判断机械臂是否必要；
3. 只保留最小可行电子配置；
4. 逐项按 2026–27 Cost Form 和 Program Guide 计价；
5. 不将规则中指定计价的机器人控制器、电池豁免等误算。

## 12. 结论

理论架构可以作为下一阶段的工程输入，但尚未达到整机制造冻结条件。当前最合理的执行顺序是：先验收购物车和道具实物 → 量尺寸 → 做独立卸载台无动力样机 → 完成乘坐车辆专业结构设计与审查 → 电气安全台架 → 固件构建与功能补全 → 无人低速测试 → 完整场地验证。

**禁止把本报告当作车辆结构安全证明、载人许可、比赛合规裁定或已经通过实机测试的证据。**
