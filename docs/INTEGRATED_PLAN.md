# 整合方案与技术决策

## 1. 目标与依据

14 天内完成一个可运行、可演示、可验收的 OMER 购物服务原型。**仅将 `3组/` 文件夹当作项目材料参考；其他旧代码、旧设计和旧方案都可以弃用或重写。**

规则审查的首要来源是仓库内 `D5/1111111-main/2026-2027年度头脑奥林匹克长期题9.30.pdf`。已对用户提供的 6 页扫描题面逐页查看，并在 [规则追踪表](RULE_TRACEABILITY_2026-27.md) 中记录题面摘要、设计约束与验收证据。仍须单独核对当季活动手册和最新官方澄清；组别仍待确认。

## 2. 任务链路

`START → ORDER_LIST_HANDOFF → VERIFY_OPERATOR_HAS_LIST → CROSS_START_LINE → CHECK_STOCK → SELECT_SUBSTITUTE → PICK_AND_LOAD → NAVIGATE_TO_CHECKOUT → CHECKOUT_VERIFY → HUMAN_OPERATED_DETACHED_UNLOAD (if required for the division) → DRIVE_CART_PAST_START_LINE → STOP_VEHICLE → RELEASE_CART → CART_SETTLES_IN_CART_AREA → COMPLETE_SIGNAL → DONE`

**官方 2026-10-01 澄清：** 计时开始时，购物清单必须交给车辆操作员，且在车辆越过 Start Line 前完成。因此清单交接是跨线的硬性前置条件，不能放到车辆出发后。2026-09-15 澄清还明确了 Shopping Area 边界及 Figure A 的 6 ft 相对位置；场地放样必须按官方图示执行，尺寸虚线不是区域边界。详见 [采购准备与设计冻结台账](PROCUREMENT_READINESS.md) 第 6 节与官方澄清页。

每个状态都应有明确的进入条件、成功条件、超时保护和可复位方式。题面要求重点是车辆推进购物车越过起始线垂直平面后停车并释放；购物车最终进入购物车区域，车辆保持在起始线上或其外侧。不得把它误写成“车辆返回停车区”。

## 3. 技术路线（允许重构）

### 3.1 主控与底盘（明确区分无人原型与载人目标）

- 主控采用 **ESP32-S3 N16R8 开发板**作为任务逻辑控制器候选，预算 ¥20–150；购买前确认 USB 下载接口和存储配置。它不是载人安全控制器。
- ESP32-S3 的 GPIO、PWM 和中断资源可用于无人原型的任务控制、传感器采集和状态机。
- **旧无人原型路线：** 低速差速两驱、两个带 AB 相编码器的 12V 减速电机、独立电机驱动器、后万向轮和刚性小底盘，只能作为无人桌面/地面原型的历史方案；不得移植为载人底盘，不得以其测试结果推定载人安全。
- **载人车辆路线：** 另行评估四轮、低重心、前轮机械转向、后轮驱动的概念架构；车架、座椅、轮组、车轴、转向、行车/驻车制动和安全电气系统必须重新设计、计算、审查与配重验证。详见 [40 kg 乘坐者载人车辆改造方案](40KG_RIDER_CONVERSION.md)。
- 无人原型固件可继续验证驱动输出安全状态、急停、编码器计数和任务状态机；这些测试不能替代载人车的机械制动、转向和结构验证。
- HC-SR04 仅用于近距离避障/停靠辅助；不宣称它能识别商品或替代视觉系统。

### 3.2 固件与引脚

- ESP32-S3 采用独立的新固件工程，不将 D5 的 Nano 引脚表或依赖直接复制过来。旧 D5 的 TB6612、nRF24、OLED、MPU6050 组合属于临时版本，可以完全舍弃。
- 引脚分配见 [ESP32-S3 引脚分配与接线安全](ESP32S3_PINMAP.md)；接线前按实际板型核验。
- ESP32-S3 GPIO 为 3.3V 且不耐 5V 输入；HC-SR04 Echo 必须分压或电平转换。编码器输出电压要先测量/核实。BTS7960 的 3.3V 控制兼容性和使能脚电路需核实。
- GPIO21 作为两块驱动器的共享使能输出，外部下拉确保复位时禁用；仅在短时运动脉冲内使能，先将 PWM 归零再禁用。须先确认驱动器输入能识别 3.3V，否则加电平转换。
- 急停必须物理切断电机驱动电源。软件复位、死机或无线失联不能使电机继续运行。
- 第一阶段不加 Wi-Fi 远程控制、OLED、IMU 或多板通信，除非核心流程已通过门槛测试。

### 3.3 缺货替代

- 货架缺货状态由明确的输入/传感器事件提供；初版可用测试开关，不宣称视觉识别已完成。
- 决策程序从候选表中自动选出唯一替代品：同类别、在预算内、最低价优先、同价按固定 ID 排序。
- 助理可展示结果，但不能通过遥控临时改选程序结果。
- 若没有合规候选，程序输出 `NEEDS_ASSISTANCE`，停止当前自动采购并记录原因。

### 3.4 商品抓取机械臂（本轮取消）

- 用户已确认优先改造为可乘坐车辆，乘客体重下限为 35 kg、额定乘客承重至少 40 kg；本轮不制作车载商品抓取机械臂。
- 删除机械臂舵机、PCA9685、夹爪、连杆、底座和专用舵机电源的采购优先级；将质量、空间和预算优先留给承载车架、座椅固定、轮组、转向、制动和防护。
- 取消机械臂不影响赛题要求的独立人力卸载装置；该装置仍须与车辆完全分离。
- 载人改造需求、现有底盘缺口、预算和验证门槛见 [40 kg 乘坐者载人车辆改造方案](40KG_RIDER_CONVERSION.md)。

### 3.4.1 旧机械臂方案归档说明

机械臂候选结构已取消，不采购、不制作、不计入本轮车辆功能。历史方案不再保留在实施步骤中。独立人力卸载装置仍按下一节执行。

### 3.5 题目要求的卸载装置（P0 规则门槛）

- 2026–2027 题面明确要求：卸载装置须原创、由队伍自制（可使用商业零件）、**不得连接在车辆上**；队员可直接使用人力操作。它须把购物车中的三件物品放到结账区域。
- 因此，现有车载 MG996R、翻斗/舱门不能作为题目规定的卸载装置。不要采购或把车载舵机当作卸货合规方案；可暂时保留作非比赛台架实验，但在比赛架构中将其从“卸载”职责移除。
- 建议采用与车辆完全分离的独立桌面/手持机构或简单导向架，由队员按题面直接人力操作。机构形式需在组别确认、活动手册与澄清复核后冻结。
- 单项验收：三件可见物品均从购物车进入结账区域；装置与车无任何连接；录像清楚显示操作过程。若在 8 分钟时限内不稳定，优先简化为可靠的人力操作机构，不要增加电机或自动化复杂度。

### 3.6 购物车与车辆返航

- 购物车采用被动拖挂和可控释放结构，优先减少独立电机和额外电池。
- 按题面顺序，车辆与购物车连接并推进购物车；结账后继续行进，直至购物车穿过起始线垂直平面，再停车并释放购物车。
- 购物车须最终静止在购物车区域（至少一个接地点位于该区域）；车辆保持在起始线上或其外侧。不能把“车辆返回停车区”当成题面要求的购物车返区，也不能只验证车辆返航。
- 在完整题面未确认前，不宣称某种释放方式已合规；任何与题面冲突的旧设计可直接舍弃。

## 4. 采购和依赖

具体型号、数量、人民币估算及物流筛选条件见 [COMPONENTS_BOM.md](COMPONENTS_BOM.md)；采购分级、设计冻结门禁和成本台账见 [PROCUREMENT_READINESS.md](PROCUREMENT_READINESS.md)。ESP32-S3 初版引脚见 [ESP32S3_PINMAP.md](ESP32S3_PINMAP.md)。采购预算需以结算价重算，并按比赛成本规则登记。电机堵转电流、驱动板持续电流、保险丝和线径必须匹配。

先建立一个独立的 ESP32-S3 固件工程，最小实现顺序为：
1. 上电安全状态与硬件急停验证；
2. 单侧电机低占空比控制；
3. 编码器计数与方向验证；
4. 超声波电平安全与读数；
5. 状态机和任务日志；
6. 全流程集成。

Python 替代决策模块是规则原型，不等于车辆固件已经集成。

## 5. 14 天版本门槛

- **M1**：底盘低速移动、硬件急停和失联/复位后的安全状态可重复。
- **M2**：编码器返航/停靠逻辑在固定测试路线可重复运行。
- **M3**：替代规则通过单元测试，输出可解释且确定。
- **M4（P0）**：独立于车辆、原创自制且可由队员直接人力操作的卸载装置，将三件物品从购物车放到结账区域；连续测试留证。
- **M5**：按题面完成结账、独立卸货、车辆与购物车过起始线、停车与释放、购物车最终停入购物车区域；完整流程连续 5 次无关键安全或规则失败。
- 未通过的功能应删减或降级，并如实记录；不允许以剧情表演掩盖技术任务未完成。
